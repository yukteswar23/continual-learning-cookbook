The episode calls for method-agnostic benchmarking at 01:10:45 . In June 2026, Parth Asawa, Matei Zaharia, Joseph Gonzalez and colleagues released one. The abstract says: “Continual learning, the ability of AI systems to improve through sequential experience, has attracted substantial interest, but no high-quality benchmark exists to evaluate it” .

11.1Why existing tests miss the point

Existing evaluations each test a proxy. Memory systems are scored on recall over past conversations. Context-compaction methods are scored on preserving full-context behaviour. Test-time-training methods are scored on loss, knowledge insertion or new-task accuracy. “These proxies do not directly test whether a system improves online by learning environment-specific latent structure across related tasks” .

11.2Vocabulary

  • A task is a sequence of problem instances.
  • An instance is one problem, such as one database question. Reward is defined per instance.
  • A step is one agent action, such as one SQL query.
  • A system is anything under test: a model plus any learning mechanism. “CL-Bench does not prescribe a specific adaptation mechanism.”
  • Variants change the environment to introduce concept drift. A schedule is the full ordered run across variants .

11.3What makes a good continual learning task

Three admission criteria “jointly define when measured improvement reflects online learning rather than static model capability” :

  1. Headroom. Initial performance must be well below the maximum, and the structure to be learned must not be recoverable from general training. Otherwise “a stronger base model and a learning system are indistinguishable”.
  2. Shared latent structure. Something discoverable, “such as codebase structure, schema conventions, opponent strategies”, must be shared across instances and never stated explicitly.
  3. Learning mechanism. Earlier instances must produce feedback that is informative for later ones: test failures, error messages, intermediate predictions.
Running example: Database ExplorationAn agent answers 40 questions about an unfamiliar SQLite database of Amazon product reviews, with a budget of 15 exploratory queries per question. The schema is deliberately obfuscated: table g2_reviews, a column vrf for verified status, and prices stored as integer cents for Electronics but float dollars for other groups. Reward is the fraction of the query budget saved. Halfway through, a migration renames tables and reformats columns, so the agent must notice which knowledge has gone stale .

These criteria rule out a common shortcut: you cannot build such a benchmark by chaining instances from existing benchmarks, because those instances “are designed to be diverse and independent”. Each task was designed from scratch and reviewed by two authors. Two or three domain experts per task then judged realism, reusable knowledge and learnability, spending on average 2.14 hours per review cycle .

The six domains are software engineering (Codebase Adaptation), database analytics (Database Exploration), epidemiological forecasting (Cohort Studies), RF spectrum monitoring (Blind Spectrum Monitoring), sales forecasting (Sales Prediction) and strategic gaming (Exploitable Poker). Codebase Adaptation and Sales Prediction run agents in a persistent terminal with full shell access .

11.4The metrics

A system processes instances \(x_1,\dots,x_N\) and receives rewards \(r_t\). A stateless system uses only the current instance, \(\pi_t = \pi(x_t)\). A stateful one also uses the history \(\mathcal{H}_{t-1} = \{(x_i, r_i)\}_{i=1}^{t-1}\), so \(\pi_t = \pi(x_t, \mathcal{H}_{t-1})\). The task reward is the stateful system’s total:

\[ r^{sf} \;=\; \sum_{t=1}^{N} r^{sf}_t . \]

A rising curve is not enough, because difficulty varies between instances and between systems: “A generically strong system may produce high reward with no learning at all while a weaker system that exploits prior experience may show lower absolute reward but actually improves over time.” Hence gain: run the same system statelessly on the same instances and subtract.

\[ g_t \;=\; r^{sf}_t - r^{sl}_t, \qquad g \;=\; \sum_{t=1}^{N} g_t . \]

“Whatever makes instance \(t\) intrinsically easy or hard for a given system appears equally in both terms. The difference isolates only the contribution of the accumulated state” .

Each task specifies a maximum average reward \(r_\text{max}\), which lets scores be compared across tasks. Normalized gain divides by the system’s own headroom:

\[ \widehat{g} \;=\; \frac{\bar r^{sf} - \bar r^{sl}}{r_\text{max} - \bar r^{sl}}, \]

and normalized reward uses a fixed external reference, the stateless reward of GPT-5.4 with ICL, so that a system’s score “does not change as new systems are added”:

\[ \widehat{r} \;=\; \frac{\bar r^{sf} - r_\text{external}}{r_\text{max} - r_\text{external}} . \]

The systems tested were full-context ICL; ICL Notepad (the agent maintains its own notes); Mem0 (automatic memory extraction with top-10 retrieval); ACE (a playbook of memories updated after each instance); and Claude Code and Codex run headless with automatic context compaction. Simple wins. Full-context ICL with Sonnet 4.6 has both the highest reward and the highest gain. Dedicated memory systems “do poorly relative to their cost”: ACE ranks tenth by gain at the highest cost. The same Sonnet model with a Notepad drops to sixth by gain, which shows “the choice of learning medium matters as much as the underlying model” .

Learning looks different in each task. Sales Prediction and Blind Spectrum Monitoring show early, clear gaps. In Database Exploration the gain shows up mostly as the stateless system’s reward “collapses to zero” while the stateful one keeps a floor. In Cohort Studies, Codebase and Poker the two curves overlap. In Cohort Studies, “experts validated the learnability of the latent structure but no evaluated system currently extracts it, appearing misled by spurious correlations” .

On cost, “no dedicated memory system dominates ICL on either cost axis”. ICL with Gemini 3 Flash gives 16.4% gain at $7.6 per run. Claude Code is the one clear exception on the frontier, with 23.9% gain and the strongest single-task gains on Sales Prediction (65.1%) and Database Exploration (43.6%) .

Stability and plasticity, measured

Variant boundaries give a natural split. Gain on the first instance of a new variant measures stability: transferring old knowledge before any feedback in the new variant. Gain within a variant measures plasticity: adapting to new information .

ICL Notepad with Sonnet 4.6 shows the most stable learning. ICL and Claude Code are the most plastic. ACE and GPT-5.4 with ICL show “virtually no stable learning”: their gains come from repeated exposure to the same variant, “offset by information loss after switches to new variants” .

11.6Try it yourself

The benchmark is open source (Apache-2.0). From the repository README :

git clone https://github.com/pgasawa/continual-learning-bench
uv sync --all-extras && source .venv/bin/activate
clbench run exploitable_poker --schedule quick_test --system icl

It needs Python 3.13+, uv and Docker. Tasks live in src/tasks/ and systems in src/systems/. The harness runs multi-episode rollouts and records traces. The paper invites contributions: “We expect CL-Bench to be a continuously improving benchmark, leveraging the open-source community to add more varied and challenging tasks.”

The authors’ own limitsSix domains do not cover all real-world continual learning. Sequences are tens of instances long, shorter than real deployments. Only context-based memory paradigms were evaluated: “we do not evaluate parametric approaches such as test-time training”, the methods of Chapters 6–10. Tasks need frontier-level models, so failure modes of smaller models may not show up .

“Naive ICL outperforms dedicated memory architectures on most tasks, and even the best system achieves only 25.4% normalized gain over its stateless baseline. Accumulated state frequently hurts rather than helps.”

Asawa et al. 2026, Conclusion

What to take from this chapter

  1. Measure learning, not capability: gain \(= r^{sf} - r^{sl}\), the same system with and without its memory, on the same instances.
  2. Good tasks need headroom, hidden shared structure, and feedback that teaches. Chained independent benchmarks will not do.
  3. Today, keeping the whole history in context beats engineered memory, and even the best system captures only about a quarter of the available headroom.
