The episode moves through the classic method families one after another: replay at 32:40, regularization at 36:10, then meta-learning and hypernetworks . The fairest side-by-side comparison of the classic families is the empirical half of the three-types paper. Every method uses the same network, the same data and the same training budget, and is judged in all three scenarios .

4.1The shared kitchen

  • Split MNIST: five contexts of two digits, assigned randomly per seed. The network has two fully connected hidden layers of 400 ReLU units. Each context is trained for 2,000 iterations with batch size 128 and Adam at learning rate 0.001. Results are averaged over 20 seeds.
  • Split CIFAR-100: ten contexts of ten classes. Five convolutional layers (16, 32, 64, 128 and 256 channels), pre-trained on CIFAR-10 and then frozen, followed by two fully connected layers of 2,000 units. Each context gets 5,000 iterations with batch size 256 and learning rate 0.0001. Results are averaged over 10 seeds.
  • Baselines: “None” trains on each context in turn with no protection (the lower target). “Joint” trains on everything at once with the same number of iterations (the upper target).

Methods that store data were given 100 examples per class. Methods with a generative model could use up to three times as many parameters .

4.2Strategy 1: context-specific components

Use different parts of the network for different contexts. Separate Networks splits the parameter budget into one small network per context, for example two layers of 100 units each on Split MNIST. XdG (context-dependent gating) switches off a random subset of hidden units per context. Both need the context label at test time, “which meant that they could only be used in the task-incremental learning scenario” .

4.3Strategy 2: parameter regularization

This is the EWC family from Chapter 2, with a penalty on moving important parameters. The paper writes EWC for context \(K>1\) with one quadratic term per earlier context (Eq. 4):

\[ \mathcal{L}^{(K)}_{\text{param-reg}}(\theta) \;=\; \lambda \sum_{k=1}^{K-1} \frac12 \sum_{i=1}^{N_\text{params}} F^{(k)}_{ii}\,\big(\theta_i - \hat\theta^{(k)}_i\big)^2 , \]

with the Fisher diagonal estimated using the model’s own predicted probabilities as soft labels (Eq. 5):

\[ F^{(k)}_{ii} \;=\; \frac{1}{|S^{(k)}|}\sum_{x\in S^{(k)}} \sum_{o} \tilde y^{\,k}_o(x)\left(\frac{\partial \log p_\theta(o\mid x)}{\partial \theta_i}\Big|_{\theta=\hat\theta^{(k)}}\right)^{2}, \qquad \tilde y^{\,k}_o(x) = p_{\hat\theta^{(k)}}(o\mid x). \]

Synaptic Intelligence (SI) estimates importance online, from how much each parameter’s movement reduced the loss during training. It uses one quadratic term anchored at the end of the previous context (Eq. 6):

\[ \mathcal{L}^{(K)}_{\text{param-reg}}(\theta) \;=\; \gamma \sum_{i=1}^{N_\text{params}} \Omega^{(K-1)}_i\,\big(\theta_i - \hat\theta^{*}_i\big)^2 . \]

The per-parameter contribution during context \(k\) sums, over all iterations \(t\), the parameter’s step times the negative gradient (Eq. 7):

\[ \omega^{(k)}_i \;=\; \sum_{t=1}^{N_\text{iters}} \Big(\theta_i[t^{(k)}] - \theta_i[(t-1)^{(k)}]\Big)\cdot\left(-\frac{\partial \mathcal{L}_\text{total}[t^{(k)}]}{\partial \theta_i}\right). \]

This is normalised by how far the parameter moved, \(\Delta^{(k)}_i = \theta_i[N_\text{iters}^{(k)}] - \theta_i[0^{(k)}]\), plus a damping term \(\xi = 0.1\), and summed over contexts (Eq. 8):

\[ \Omega^{(K-1)}_i \;=\; \sum_{k=1}^{K-1} \frac{\omega^{(k)}_i}{\big(\Delta^{(k)}_i\big)^2 + \xi}. \]

4.4Strategy 3: functional regularization

Instead of protecting weights, protect the function: keep the old input–output mapping at a set of anchor points. Learning without Forgetting (LwF) uses the current context’s inputs as anchors, with knowledge distillation from the previous model \(\hat\theta^*\) (Eq. 9):

\[ \mathcal{L}^{(K)}_{\text{func-reg}}(x,\theta) \;=\; -\sum_{k=1}^{K-1}\sum_{o\in O_k} p^{T}_{\hat\theta^*}(o\mid x)\,\log p^{T}_{\theta}(o\mid x), \]

with temperature-raised probabilities, \(T = 2\) (Eq. 10):

\[ p^{T}_{\theta}(o\mid x) \;=\; \frac{\exp\!\big(z_o(x,\theta)/T\big)}{\sum_j \exp\!\big(z_j(x,\theta)/T\big)}. \]

FROMP does functional regularization in a Bayesian framework. Its anchor points are stored “memorable” examples from past contexts, chosen by the relevance score \(r(x) = \sum_{o} p_\theta(o\mid x)\big(1-p_\theta(o\mid x)\big)\) .

4.5Strategy 4: replay

Complement each new context’s data with data that represents the past. Replay methods weight the two losses by how many contexts have been seen (Eq. 16):

\[ \mathcal{L}_\text{total} \;=\; \frac{1}{N_\text{contexts so far}}\,\mathcal{L}_\text{current} \;+\; \Big(1 - \frac{1}{N_\text{contexts so far}}\Big)\,\mathcal{L}_\text{replay}. \]
  • ER (experience replay): sample stored examples from a buffer and add their ordinary classification loss.
  • A-GEM: the same buffer, but replay acts as a constraint. If the current gradient would increase the replay loss, project it (Eq. 19): \[ g^* = \begin{cases} g_\text{current} & \text{if } g_\text{current}^{\top} g_\text{replay} \ge 0,\\[4pt] g_\text{current} - \dfrac{g_\text{current}^{\top} g_\text{replay}}{g_\text{replay}^{\top} g_\text{replay} + \gamma}\, g_\text{replay} & \text{otherwise,}\end{cases}\qquad \gamma = 10^{-7}. \]
  • DGR (deep generative replay): no stored data. A variational autoencoder learns to generate past inputs, and a copy of the old classifier labels them. The VAE loss is a latent term plus a reconstruction term (Eqs. 20–22). The latent term is the KL divergence from the encoder’s Gaussian to the standard normal prior (written here in its standard form), and the reconstruction term is a squared error over pixels: \[ \mathcal{L}_\text{latent} = -\tfrac12\sum_{j=1}^{N_\text{latent}}\Big(1+\log\sigma_j(x)^2-\mu_j(x)^2-\sigma_j(x)^2\Big),\qquad \mathcal{L}_\text{recon} = \sum_{p=1}^{N_\text{pixels}}\big(x_p - \tilde x_p\big)^2. \]
  • BI-R (brain-inspired replay): replays generated internal representations rather than raw pixels, with conditional replay and gating.

4.6Strategy 5: template-based classification

Learn a template per class, then classify by which template fits best. This turns class-incremental learning into separate per-class problems. The Generative Classifier trains one small VAE per class and classifies by likelihood (Eq. 24):

\[ o^* \;=\; \arg\max_o \; p(x\mid o), \]

estimated with 10,000 importance samples. iCaRL keeps exemplars chosen by “herding” and classifies by the nearest class mean in feature space (Eq. 30):

\[ o^* \;=\; \arg\min_{o} \;\big\|\psi_\phi(x) - \mu_o\big\| . \]

4.8Reading the tables

Everything works in Task-IL. Not everything survives Class-IL. “With task-incremental learning, almost all tested methods performed well compared to the ‘none’ and ‘joint’ baselines, with domain-incremental learning the relative performances of many methods dropped considerably and with class-incremental learning they decreased even further” .

EWC and SI fail completely at Class-IL. On Split MNIST they score 20.64% and 21.20%, essentially the 19.89% of no protection at all. The authors give the reason:

“with class-incremental learning, learning a new context (for example, distinguishing ‘2’ and ‘3’) while preserving what was learned before (for example, distinguishing ‘0’ and ‘1’) is not enough; it is also needed to combine information from different contexts (for example, for distinguishing ‘1’ and ‘2’).”

van de Ven et al. 2022, Discussion

They conclude that for classes never seen together, “it might be unavoidable to use either replay, which allows for comparing between classes from different contexts during training, or template-based classification, which allows for comparing between classes from different contexts during inference” .

Plain replay is a strong baseline. “Perhaps surprisingly, on all experiments ER comfortably outperformed A-GEM”, even though A-GEM costs more. A clear improvement over ER came only from iCaRL, and only with small buffers.

Generating replay is harder for complex inputs. DGR does well on Split MNIST (90.35% Class-IL) but drops to 9.67% on CIFAR-100. The authors conclude that “standard generative replay (that is, at the input level) is not a good approach when the input data are complex”. Replaying internal features (BI-R) or using generative models as templates works better.

Task-IL’s bar is set too low. Most methods beat the “None” baseline, but most do worse than simply training a smaller separate network per context: Separate Networks scores 99.57% on MNIST and 76.83% on CIFAR. To beat that “positive forward or backward transfer between contexts is necessary, but achieving such positive transfer is not trivial” .

Experience replay (ER)

Recipe 4.1 · the strongest simple baseline

You will need

  • A memory buffer: \(B\) examples per class (100 in the comparison)
  • The right to store past data, which privacy or licensing may forbid
  • One extra forward and backward pass per step for the replayed batch

Method

  1. Train on context 1 with the ordinary loss.
  2. At the end of each context, add \(B\) random examples of each new class to the buffer.
  3. In every later iteration, draw a replay batch from the buffer the same size as the current batch.
  4. Minimise \(\tfrac{1}{N}\mathcal{L}_\text{current} + \big(1-\tfrac{1}{N}\big)\mathcal{L}_\text{replay}\), where \(N\) is the number of contexts so far.
When to use itIt is among the top performers in all three scenarios on Split MNIST, and it does not need context labels at test time. The cost is storage, and the memory grows with the number of classes.

What to take from this chapter

  1. Parameter regularization (EWC, SI) protects old tasks when the task is known, and fails almost completely when the model must choose among all classes.
  2. Replay, from a buffer or a generator, is the only strategy among the top performers in all three scenarios. The simple version is hard to beat.
  3. Class-incremental learning needs a way to compare classes from different contexts, either during training (replay) or during inference (templates).
